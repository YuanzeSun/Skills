# 实验记录

按实验大小保留必要字段即可。可用 Markdown 配合 CSV/JSON 原始数据，不要求固定文件名或独立平台。下面的字段用于说明记录内容，不能替代真实结果。

## 开始前

- **问题与假设**：当前瓶颈、改动减少的工作、预期趋势及能推翻解释的结果。
- **对照**：基线/候选、实际执行步骤、共同部分、变化因素，如何确认目标分支命中。
- **指标与判据**：主要指标、单位、统计单位与汇总方法、正确性/质量/资源约束。
- **运行安排**：代表负载与关键边界、配对与顺序、预热和正式计时范围、预计资源及停止条件。

## 每次运行

| 内容 | 应留下的信息 |
| --- | --- |
| 标识与状态 | 唯一运行标识，开始/结束时间，完成、失败或中断，重试关联 |
| 实际代码 | 仓库与提交、未提交补丁或哈希、构建/库版本、关键环境 |
| 可重跑入口 | 命令、配置、输入或生成方法、seed、模型/数据版本 |
| 执行条件 | 设备与拓扑、资源占用、顺序、缓存状态、实际分支、计时方法 |
| 原始结果 | 逐次计时、工作量、正确性/质量、资源占用、失败与必要日志 |

源码或配置改变后使用新运行标识。写入中间结果时保留先前已完成记录；重启不能把旧失败或部分结果覆盖成新成功。分析脚本引用明确输入文件，避免把不同实现的数据混成一组。

## 收敛本轮实验

- 确认基线和候选实际执行的工作、代码与运行条件可比，且候选命中了目标路径。
- 根据正确性、目标指标、资源代价和运行波动，判断假设得到支持、被推翻，还是当前仍不能判定。
- 若继续，选择能区分剩余原因的最小下一步；若采用或放弃方案，限定在已验证的工作负载和环境范围内。
