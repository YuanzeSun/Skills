# 测量与判断

只选择影响当前结论的部分，不把本文变成每次都要完成的全套流程。

## 从机制推出对照

机制解释应给出可以失败的预测，而不是将“测得更快”换一种说法。

| 假设 | 能区分原因的比较 | 同时观察 |
| --- | --- | --- |
| 融合减少中间搬运 | 固定计算与精度，分开/融合执行；改变中间数据量 | 实际读写、启动次数、资源占用及总耗时 |
| 流水隐藏等待 | 相同分块与布局，串行/重叠执行；改变块数或两阶段工作量 | 时间线、同步、缓冲占用、总完成时间 |
| 预取或卸载节省设备内存 | 常驻/预取，核对相同负载与约束 | 实际峰值和常驻内存、传输量、暴露的等待、完整任务耗时 |
| 编译优化减少运行工作 | 固定程序及输入，记录优化是否命中 | 编译耗时、生成代码、运行耗时；冷启动与稳态分开 |
| 通信优化减少传输或同步 | 固定正确性及通信规模，改变消息大小和并行数 | 实际字节数、集体操作完成时间、最慢参与方和应用耗时 |

例如一组生产者/消费者处理 n 项任务，每项耗时分别为 c、v，串行约 n(c+v)，理想流水约 c+v+(n−1)max(c,v)，再加同步等成本。先预测何时可隐藏等待，再用实际时间线和对照检查；n 应对应这组执行单元的任务数。

## 对照的含义

- 对照实验用来解释原因，部署比较用来判断最终价值，二者的比较对象可以不同。例如隔离卸载机制时固定请求与缓存预算；判断实际部署价值时还要观察释放内存后可支持的容量。分别命名和解释结果。
- 候选改变精度、布局和任务顺序时，把这些因素记清。声称“K 复用的收益”前，要确认对照没有同时换掉整个矩阵算法。开关未命中则是同计算比较，不是优化消融。
- 相同原始负载不一定有相同执行工作量。生成可能改变输出长度与路由，调度可能改变 batch；记录这些变化，必要时用固定执行轨迹帮助定位，再回到真实负载确认。

## 异步、图与缓存

设备事件通常只计相应流上的区间。多个流共同完成任务时，要建立依赖或在最后等待完成事件；CPU 端只测调用返回会漏掉异步工作。同步位置在基线与候选中一致，且不能为了计时把原本重叠的流水强制串行。

图捕获、预热和编译单列。正式重放应改变输入，核对输出、状态和缓存确实随之更新；持久缓冲地址、跨流事件和复用时机与生产调用一致。短算子可一次计多次调用来降低测量开销，但这仍属于同一运行内的重复；会改变缓存或状态的操作应保持真实语义。

预取实验明确区分主存→设备、设备间复制和片上预取。记录实际传输字节、有效带宽及未隐藏的等待；锁页内存、固定缓冲和双缓冲是实现手段，效果以总耗时和内存实测为准。

## 波动与统计单位

先画清层次：输入/数据集 → 独立进程或服务启动 → 捕获或运行顺序 → 重复计时。每一层代表不同变化来源。更多重放可以提高一次运行内的计时精度，不能替代独立启动或不同工作负载。

基线和候选尽量配对，在各独立运行中平衡先后顺序。随时间漂移时，可交错测量并记录运行状态；重复 A/A 用于观察测量方法的波动。A/A 与候选的差异一起判断，不设通用的“收益小于某百分比就无效”。

按声明的总体选择汇总单位。对固定输入只重复启动的实验，结论针对这些输入；同一启动内多个 seed 不能代表跨启动稳定性。区间估计应保留配对与分组关系，不把层次不同的样本混在一起。种子相同也不自动保证并发调度、通信顺序或生成过程相同。

耗时减少率为 (T基线−T候选)/T基线，吞吐提高率为 (Q候选−Q基线)/Q基线，二者不直接互换。需要总体吞吐时按总工作量/总时间计算；按输入平均百分比时写明其含义。异常记录保留；只有明确的测量失效按事先规则排除，并同时记录理由和排除数量。

## 工作负载与边界

选取真实分布、典型规模、尾部和机制相关边界，再补少量代表性扰动。阈值候选需测两侧与邻近点，区分实际请求量与补齐后的执行量。数据类型、维度或索引范围变化时，优先覆盖会改变分支或资源需求的位置，而非穷举无关组合。

调优阶段可以快速筛选；确定方案后，用未用于筛选的输入或独立运行复核。预先约定时间/资源上限和停止条件：支持采用、确认退化、定位到明确阻碍或用完预算时收尾，记录尚不确定的项目。不要按正负结果决定是否继续采样。

## 系统指标按目标选择

| 项目 | 需要对齐的负载 | 常见目标与代价 |
| --- | --- | --- |
| 推理服务 | 输入/输出长度、到达方式、并发、前缀复用、采样与停止规则 | 输出吞吐、首 token 延迟、逐 token 延迟、尾延迟、成功率、内存容量 |
| 训练 | 有效全局 batch、数据顺序、优化器、精度、并行方式 | step 时间、样本吞吐、内存、达到同等质量的时间；改变 batch 时补充收敛比较 |
| 编译器 | 程序和形状、编译缓存、运行次数 | 编译时间、首次运行、稳态执行、代码大小、结果正确性 |
| 通信/存储 | 消息或记录大小、拓扑、参与方、缓存冷热与并发 | 完成时间、有效吞吐、尾延迟、CPU/设备占用、数据完整性 |

只选与目标相关的指标。分布式任务计到所有必要参与方完成；同时查看单卡与全局指标、最慢参与方。服务吞吐按成功完成的工作计算，同时保留失败、超时、未完成请求与完整观察窗口。延迟分位数按请求汇总，不把各 rank 的 p99 再简单平均。

## 采用与范围

局部测量、真实调用和系统测量按问题推进，不要求每个小修改都跑完整服务。采用条件应对应项目目标与代价：资源受限时，内存减少但耗时略增可能有价值；延迟目标下，同样变化可能不合适。

评估范围时，把接口要求、已测性能交叉和覆盖空缺分别记录。宽泛机制若只有零散测点，不急于固化成大量分支；先选能确认趋势的少量边界对照。出现稳定退化时查原因，优先调整通用实现；确需选择策略时，用最简单且有证据的规则。
