# 个人笔记维护

让已有笔记更容易查找、更连贯，同时保留作者的语言、实测经历和信息。用户当前明确要求优先于这些默认偏好

## 编辑范围

- 先分清任务是解释、审查、试改还是实际编辑。用户说“先告诉我”“先别改”“批准再改”时，只读和汇报；批准后只落实批准的编号和内容，不顺带修改未批准项
- 延续已授权的维护工作，不为普通、可逆的排版调整反复索要许可。需要审批时，先给出具体、可核对的改法，让用户批准明确结果
- 用户要求复制后编辑时，先复制并确认副本内容完整，再编辑副本；后续沿用已确认的整理版，不反复复制、不改原版。技能不绑定固定页面 ID
- 用户要求保留、还原某种说法时，尊重该边界；后续查证不等于获得修改许可。个人经历和讨论中的例子也不能自动变成普遍事实
- 用户只要求试改一段时，先限制在这一段。用户要求审查全文时，要检查全文，不能只修他举出的几个例子
- 创建或更新本技能不等于授权修改笔记，也不自动授权创建 Notion 页面、安装工具或向其他人发消息

## 分类和条目

- 按每一段真正讨论的主题分类，不按出现的关键词、软件名或相邻位置分类。审查章节归属、圆点间关系和圆点内部各段的关系
- 相近内容、重复说明和相关代码块可以合并；但不要为了合并而合并。独立主题该单列就单列，一句话也完全可以是独立圆点
- **只有内容包含若干小点，需要统一概括成一类时，才给圆点起短标题**。不是所有圆点都要先写标题再写正文；不要强行套同一模板
- 标题短而直接，不写长摘要，不加末尾冒号，不写“标题｜副标题”。默认不添加开头目录、导语或整理说明，不堆三级标题和加粗小标签制造层级
- 正常保留必要章节和二级标题。大类应覆盖其内容，不用“其他”“常用”掩盖不相干主题。显示、启动、蓝牙不属于存储
- 系统设置和常用软件放回对应操作系统。用户认定的一组 Windows 常用软件放 Windows，不因用途广泛就移到生活类
- 有华为相关记录时，保留其独立体系；CANN、NPU、HCCS、HIXL、相关容器、池化和机器记录不要混入普通 GPU、容器或互联章节
- 不合理合并的典型例子：Shell 与 Safari、深拷贝与 monkey patch、Worktree 与 git blame、睡眠模式与吞吐指标
- 快捷键条目不夹多桌面、热点设置和系统工具；Homebrew 不包揽系统自带 SQLite、Command Line Tools 和系统更新历史；卡顿排查不等于空间清理
- 移动文字时一并考虑代码、表格、图片、使用条件和前后指代；不能让“上面”“下面”“同上”移动后失去对象

## 措辞、段落和标点

- 用户要求轻改语言时逐条阅读，修顺句子、去冗余、重排或拼接段落。不能只搬分类就算完成，也不能把个人记录重写成正式、过度严谨的教程
- 保留“我感觉”“之前遇到过”等口吻、历史版本和实测条件。不凭空增加“似乎”“据说”“我不确定”，更不能把作者的确定记录降格成猜测
- 大部分工作在原内容基础上重构或改写；只在理解所必需时小幅补充，不扩写成百科，不添加无关知识
- 一段围绕一个连贯意思。定义、解释、直接后果可接起来；独立问题、步骤和体验适当分段。既不整点堆成大段，也不每句话机械换行
- Notion 有同块内换行和多个对齐的独立块：紧密连续内容可用同块换行，独立语义用不同块；保持同层对齐，不自动给圆点里的段落再加小标题或嵌套圆点
- 中文正文段尾默认不加“。”，但段内完整句之间仍用句号。合并换行后重新断句，不用逗号硬接完整句；紧密并列可用分号
- 保留必要的句中冒号、网址、路径及代码语法。标题去冒号、段尾去句号都不做全文字符替换
- 获准修正后直接保留正确结果，删掉“这一点前面记错了”“具体见下面原有的提醒”“这里已统一”等编辑过程话语；不要留旧错句再叠一层错误提醒

## 指令和代码

- 每个条目主要说明的指令，第一次出现在正文时加行内代码；后续不必处处重复。按语义判断主角，不把全文所有英文和命令名批量标为代码
- 例如：`less`是分页阅读器，不像cat那样全部打印；Space下一页，b上一页。这里只标less，Space、b是按键，cat是旁带比较，都不标
- 权限条目首次主要说明可写成“`chmod`改权限，`chown`改所有者和用户组”
- 真代码、命令和函数可以标代码。普通参数名、概念、软件名、按键不滥标；一段不出现大量零散代码标记。连续参数或配置需要集中展示时，改为一个代码块
- 代码块与所属圆点保持正确父子关系和统一对齐。块内只修有问题的缩进、注释对齐和分组，已经合适的不动；保留 Python、YAML、Shell 续行和拓扑树的有效缩进
- 只合并同主题、相同或兼容语言、执行顺序清楚的代码；无关命令、不同环境和互斥示例该拆就拆，不能为了少几个块混在一起
- 排版整理不应悄悄改变代码行为；技术修改另按查证和授权范围处理

## 查证和不确定表达

- 区分个人偏好、实测经历、条件性事实、待验证原因和历史版本。“可能”“通常”有时表达必要条件，不能见到就删
- 只要求指出问题时，只提示能确认的明显错误；拿不准的不凭空标错、不加警告。用户主动要求盘点不确定表达时，再列出猜测、未验证机制、记忆数字及缺失版本条件
- 技术查证优先官方文档、项目源码和原论文，说明确认什么、适用什么条件、还有什么不能确认。当前版本不能覆盖旧版本的真实经历
- 不用通用原理推断某次故障的唯一原因；性能阈值、设备页大小、链路带宽和机器拓扑不能变成无条件通则
- 编号审批保持编号、原句和结论一一对应，执行前核对最近的批准清单，不能混用旧清单的同号条目
- 残句只有意图清楚时才补全。删掉“但”“如果”“位于……”等悬空部分，不等于补齐信息；汇报时区分“删残句”“改成完整提示”和“查证补全逻辑或位置”
- 获准删除某模式相关内容时，删除对应说明和失去意义的对比段，不连带删除一般原理、其他模式和独立编译记录

## 链接和 Notion 编辑

- 先读取当前页面，保留用户期间的手动修改；写 Notion 前读取连接器的 Notion-flavored Markdown 规范，延续原有块类型
- 普通文字、文件名、扩展名、函数名和本地路径可能被误识别为网址，例如setup.py、AGENTS.md、set_env.sh、id_rsa.pub、.NET、.ps1和.so；不能因为看起来像域名就保留链接
- 去掉误链接要保留可见文字；真正的引用、下载地址、邮箱和有访问用途的域名保留。域名链接不要吞进前面的中文或mihomo等软件名；配置字符串中的域名按配置呈现
- Notion可能把去掉链接或转义后的文件名再次识别成链接。必要时对文件名、路径和真代码用少量行内代码，普通文字与扩展名间适当留空格；避免整句链接化。不要靠不可见字符破坏复制内容，不把整段变成代码
- 优先精确局部修改，不为小调整重建全文。大幅重组确有必要时，先留快照、做内容守恒核对，保留媒体、表格和子页面，防止遗漏与重复
- 报错、警告或写入结果不确定时，先读真实状态，再重试未完成部分；不要盲目重复整个批次。遵守连接器的读取和验证规则

## 收尾

- 对照本次请求和明确授权检查每项去向、排除项；移动内容原处不留副本，删除后不留悬空标题、引导句和指代
- 检查标题、分类、圆点层级、段落连贯、段尾句号、主要指令首次标记及无关词未被代码化
- 结构调整核对代码内容、缩进、图片和表格；链接修复检查保存后的链接是否复发，不能只凭写入成功宣称已修好。必要时集中回读一次，不逐处反复抓取全文
- 简短汇报实际改了什么、仍缺什么；用户要求复述新增内容时，聊天里给出实际写入的文本和代码。只审查时不假称已编辑
